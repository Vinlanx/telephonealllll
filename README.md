# ВАЖЛИВЕ ОНОВЛЕННЯ — TURN

Старі безкоштовні TURN-сервери PeerJS (`eu-0.turn.peerjs.com` / `us-0.turn.peerjs.com`) більше не використовуються: сервіс був закритий. Через це mobile ↔ Wi‑Fi часто зависає на «З’єднання…», якщо прямий P2P не проходить.

## Як увімкнути робочий TURN (Metered Open Relay)

1. Створи безкоштовний акаунт Metered.
2. У Dashboard створи TURN credential.
3. Скопіюй назву застосунку (`appName`) і credential-scoped `apiKey`.
4. У `config.js` зміни:

```js
meteredTurn: {
  enabled: true,
  appName: "ТВОЯ_НАЗВА",
  apiKey: "ТВІЙ_CREDENTIAL_API_KEY"
}
```

5. Commit зміни на GitHub Pages і на обох пристроях онови сторінку. Якщо PWA кешує старі файли — закрий усі вкладки сайту та відкрий його заново.

`apiKey` тут саме credential-scoped ключ для отримання ICE-конфігурації; не вставляй у frontend account Secret Key.

# Лінія — простий WebRTC-телефон для GitHub Pages

Статичний голосовий дзвінок 1-на-1 без акаунтів і номерів телефону.

## Що вже є

- full-duplex голос через WebRTC;
- Opus ставиться першим у списку аудіокодеків, якщо браузер дозволяє;
- signaling через сумісний PeerServer Cloud (`0.peerjs.com`);
- STUN + TURN fallback;
- приватне посилання-запрошення з випадковим секретом;
- прийняти / відхилити / завершити дзвінок;
- mute;
- вибір мікрофона (особливо корисно на ПК);
- перемикачі `Прибрати ехо`, `Прибрати шум`, `Вирівнювати гучність` — **усі ВИКЛ за замовчуванням**;
- перемикачі можна змінювати під час дзвінка;
- показує `Пряме P2P` або `TURN relay` і приблизний ICE RTT;
- PWA-маніфест та service worker;
- жодних CDN або сторонніх JS-бібліотек у клієнті.

## Як це працює

1. GitHub Pages віддає `index.html`, CSS та JS.
2. Обидві сторони підключаються по WebSocket до signaling-сервера лише для обміну WebRTC offer/answer/ICE.
3. Голос іде через WebRTC напряму між браузерами. Якщо NAT не дозволяє прямий маршрут, WebRTC може використати TURN relay.

Signaling не є сховищем дзвінків і не потрібен для передачі аудіопотоку після встановлення WebRTC-маршруту.

## Розгортання на GitHub Pages

### Варіант без командного рядка

1. На GitHub натисни **New repository**.
2. Назви його, наприклад, `liniya` і зроби **Public**.
3. У репозиторії: **Add file → Upload files**.
4. Завантаж **усі файли з цієї папки в корінь репозиторію**.
5. Натисни **Commit changes**.
6. Відкрий **Settings → Pages**.
7. У **Build and deployment → Source** вибери **Deploy from a branch**.
8. Branch: **main**, folder: **/(root)** → **Save**.
9. Після публікації адреса буде приблизно:
   `https://ТВІЙ_НІК.github.io/liniya/`
10. Переконайся, що сайт відкривається через **HTTPS**.

## Як користуватися

### Ти

1. Відкриваєш сайт.
2. Чекаєш зеленого статусу **Готово**.
3. Натискаєш **Створити посилання**.
4. Копіюєш/надсилаєш посилання.
5. Не закриваєш вкладку.
6. Коли прийде дзвінок — **Прийняти**.

### Співрозмовник

1. Відкриває твоє посилання.
2. Чекає статусу **Готово**.
3. Натискає **Подзвонити**.
4. Дозволяє браузеру мікрофон.

## Обробка мікрофона

За замовчуванням:

- Прибрати ехо — ВИКЛ
- Прибрати шум — ВИКЛ
- Вирівнювати гучність — ВИКЛ

Якщо використовуєш динамік телефону і співрозмовник чує власний голос — увімкни **Прибрати ехо**.

Якщо навколо вентилятор/дорога/клавіатура — спробуй **Прибрати шум**.

Якщо голос то тихий, то гучний — спробуй **Вирівнювати гучність**.

Деякі браузери не підтримують усі три параметри. У такому разі відповідний перемикач буде недоступний або браузер може повідомити, що не зміг застосувати параметр.

## Вибір мікрофона на ПК

Натисни **Перевірити мікрофон** і дозволь доступ. Після дозволу браузер покаже назви доступних аудіовходів. Якщо їх кілька, з'явиться список **Мікрофон**. Його можна перемикати навіть під час дзвінка.

## Що означає статус маршруту

- **Пряме P2P** — WebRTC зміг побудувати прямий ICE-маршрут між пристроями.
- **TURN relay** — аудіо ретранслюється TURN-сервером, тому затримка може бути більшою.
- **RTT N мс** — приблизний round-trip time ICE-маршруту, а не точна одностороння затримка голосу.

## Важливі обмеження

- Публічний `0.peerjs.com` — сторонній signaling-сервіс. Якщо він недоступний у конкретній мережі, дзвінок не почнеться.
- Публічний TURN також не дає гарантії доступності або пропускної здатності.
- Для максимальної надійності наступний крок — свій PeerServer signaling + свій coturn TURN на іншому домені/сервері.
- Посилання-запрошення містить секрет. Не публікуй його відкрито. Будь-хто, хто має актуальне посилання, може подзвонити, поки твоя вкладка онлайн.
- GitHub Pages є публічним статичним хостингом. Не клади в репозиторій паролі, приватні TURN credentials або інші секрети.

## Якщо хочеш замінити signaling

Відкрий `config.js` і зміни:

```js
signaling: {
  host: "твій.домен",
  port: 443,
  path: "/",
  key: "peerjs",
  secure: true
}
```

Сервер повинен говорити протоколом PeerServer (`peerjs-server`).

## Якщо хочеш свій TURN

У `config.js` заміни/додай `iceServers`, наприклад:

```js
iceServers: [
  { urls: "stun:your-domain.example:3478" },
  {
    urls: "turn:your-domain.example:3478",
    username: "...",
    credential: "..."
  }
]
```

Не клади довгоживучі приватні TURN credentials у публічний GitHub-репозиторій для серйозного використання; краще видавати короткоживучі credentials сервером.
